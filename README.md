# TomoriCup · 高松灯杯

本仓库主要用于陈列已有实际内容、可以阅读或体验的项目。主办人的现有项目、参赛者的旧作和本次征集收到的作品都可以在这里展示；每件作品应有清楚的署名、介绍和阅读或体验入口。

高松灯杯的[正式征集通告](https://huangblac.com/gaosongdeng-cup.html)是投稿、评选、奖励及公开收录规则的唯一来源。通告首次成功公开时开始接稿；此前提交的 PR 不计入本届有效投稿，可在开放后重新提交。截止为 **2026 年 11 月 22 日 00:00（北京时间）之前**。

## 项目索引

本仓库尚未收录具体作品。项目加入后，这里会逐项列出名称、作者、内容简介、阅读或体验入口，以及“参赛”或“仅展示”的状态。索引只列已有实际内容且公开可访问的项目，不把想法或空目录当作作品。

一件作品对应一个 `works/<作者标识>/<作品标识>/` 目录，目录内的 `README.md` 说明怎样阅读或体验。主办人的现有项目也可以陈列，但应标为“仅展示”，不参加正式评分、排名或获奖。邮件投稿的原件和原始压缩包只用于核对，不直接上传；仓库收录的是经检查、获准公开的作品文件及使用说明。

## 代码类作品如何提交

1. Fork 本仓库，将一件作品放到 `works/<作者标识>/<作品标识>/`。一人可提交多件不同作品；每件作品独立建目录和 PR。同一作品的更新留在原 PR。
2. 在作品目录放一份 `README.md`，写明作品名称、作者及团队分工、如何运行或阅读、AI 参与方式，以及所用第三方素材的来源。可用 GitHub 用户名作公开署名，不必写真实姓名。
3. 发起 PR 时填写模板。PR 创建时须已有实际可评内容；空 PR 不占位。PR 创建时间和作品内容均须在截止前，截止前的最后一个有效版本用于评审。合并表示收录，不代表获奖。
4. 私下联系方式通过正式通告公布的邮箱提供。请勿把邮箱、收款信息、密钥或不愿公开的资料写入仓库、PR 或 Issue。

文字、网页、PPT 等作品也可以邮件投稿；旧作、团队作品和使用 AI 的作品均可参加，没有字数或人工写作比例门槛，但每件作品须有实际内容。邮件投稿及附件过大时的下载链接规则见正式通告。[Issue](https://github.com/HuangBlac/TomoriCup/issues) 用于规则问题、收件疑问、评审异议及必要时的同分投票，不是投稿入口。

## 公开与作品权利

投稿即授权活动在本公开仓库收录和展示作品及作者选定的署名。请确认自己有权公开所用内容。公开收录没有授予其他读者复用、改编或再分发作品的额外许可；GitHub 平台允许浏览和 fork 公开仓库。作者可按正式通告提出撤回，但既有提交历史及 fork 可能仍可见。

本仓库不对参赛作品统一附加开放复用许可证。若某件作品另有作者自行声明的许可，只适用于该作品声明的范围。
